# Advisor Annotation Guide

The repository includes `data/review.csv`, a completed sampling package for human review. It contains 800 low-margin postings selected by active learning and 200 authorization-language candidates mined from the full 785,741-row source.

## Required fields

- `advisor_role_fit_label`: one of `high_fit`, `medium_fit`, `low_fit`, or `unclear`.
- `advisor_authorization_label`: one of `explicit_restriction`, `explicit_availability`, `authorization_required`, `no_evidence`, or `ambiguous`.
- `advisor_action`: one of `forward`, `hold`, or `investigate`.
- `review_notes`: short evidence-based rationale.

## Review rules

1. Judge role fit independently from work authorization.
2. Use only the posting text in the row; do not infer sponsorship from the company name or recruiting source.
3. Mark authorization as `no_evidence` when the source does not state it explicitly.
4. Use `unclear` when core role information is missing.
5. Escalate reviewer disagreements instead of forcing silent consensus.

The annotation columns are intentionally blank because genuine advisor judgments cannot be generated by the model being evaluated.
